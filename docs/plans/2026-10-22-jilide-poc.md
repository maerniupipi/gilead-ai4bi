# 吉利德 AI4BI POC 实施计划

日期 2026年10月22日。分支 `jilide-poc`。以用户最新确认的 MySQL 和强生实验中心为实施依据。

## 目标与架构
复制 ReAct 当前代码与 Git 历史，使用强生项目的阿里云 MySQL 8.0 实例建立独立业务库 gilead_poc 与控制库 gilead_agent_loop。保留 Vue 3 与 FastAPI 持久化 Agent Loop，适配强生原生实验中心的 SSE 和 trace 查询接口。实验中心负责知识、SQL 与执行，ReAct 负责对话编排和证据核验。主协调模型保留原 ReAct 兼容配置，未新增百炼接入。

## 基础工作
1. 副本分支为 jilide-poc，来源提交 71922d25f4862034ebeb904cd9b0af3491c60b27；原目录保持原状。
2. 建立两个独立 MySQL 库与专用账号，按六表 133 列结构生成可复现模拟数据。
3. 通过强生平台 API 注册吉利德数据源 18，并测试连接；不绑定原强生实验室的 API 调用 ID。
4. 适配原生实验中心，使用同次 trace 的成功 SQL 执行结果；关闭演示与旧数据回退，独立知识目录与凭证。
5. 核对结构、金额、同比、环比、只读权限；编制中文 Word 方案、架构图、链路图及验收矩阵。

## 后续实施顺序
1. 建立吉利德独立知识库，发布实验室，绑定数据源 18 和 KPI 示例，取得 API 调用 ID 并绑定内部兼容域 actual，做真实问答验收。
2. 实施 Gilead DDI 授权策略，可信身份映射当前生效的 HCO TA BU 范围，统一覆盖文字、图表、报表和导出。
3. 完成标准 DDI 报表、口径展示、图表切换、敏感词、水印、推荐、反馈与复用技能。
4. 接入 Okta 和企业微信，补齐模板文档、更新通知、用量审计、缓存失效及 Azure 中国生产部署。
5. 对 32 项 RFP 逐条验收并完成知识转移。优先级只代表实施顺序，不排除任何合同要求。

## 复核与边界
至少完成需求覆盖、技术与数据口径、交付事实与版式三轮复核。已实现、已验证和待实施分别记录。当前共享 RDS 未启用 TLS，本次模拟环境沿用其既有连接方式，未修改共享实例参数；正式环境的私网、TLS、SSO 及区域授权仍需按 RFP 验收。
