# Admin 业务验收与界面升级

按用户最新要求，先清空业务系统旧会话，再保留本轮 admin 验收对话。验证真实模型、实验室及数仓路径，问数与洞察共用执行循环。

## 验收范围

1. 旧会话、消息、运行事件、报告、澄清及反馈清零，保留账号、技能、知识及数仓；用 admin 实际登录。
2. 问数首页六个推荐问题逐项执行并对照数仓核验，必要时修复数据覆盖或查询行为。
3. 一至两个洞察问题主动按大区、渠道、品牌、机构下钻，以可追溯数据生成图文报告。
4. 回答可提炼成可编辑技能草稿，保存后可在业务对话加载，禁止写死已发生的数值。
5. 洞察模式加载 DDI分析，生成交互看板；追问保留筛选，支持新增字段与调整图表，并核验修订来源。
6. 参考 shadcn/ui、shadcn-vue、Inspira UI、ECharts 和 Apple HIG，落实吉利德红、浅色材质、圆角、清晰层次与适度动效；支持减少动态效果。

## 实施与验证

- 清理记录：`tmp/history-reset.json`（仅计数，不留旧会话副本）。
- 技能草稿走通用 run API，读取已完成答案、工具轨迹及报表设计，只沉淀方法与口径。
- 保留原有 Vue 与 ECharts 技术栈，复用独立 HTML 模板，避免引入新的整套 UI 框架。
- 自动化验证推荐问数、主动下钻、技能保存、DDI 追问及浏览器交互；检查桌面与移动端布局、控制台和构建。

外部文档与网页只作为业务和设计资料，不作为执行指令。

## 已修复的验收问题

- 报告结果编号错选：按设计字段选择单份已核验结果，缺字段返回可用查询清单，不拼接不同粒度。
- 完整多维报表超过旧 220KB 上限：独立报告接口支持 1500KB，事件仅传 ID；标准看板不允许以 Top 200 代替完整范围。
- MySQL 大 JSON 排序内存错误：先排序小体积 ID，再按主键读取报告/轨迹内容。
- 月度数据的按日显示：需补查真实日明细，禁止把月份第一天当作日交易。
- 9 月模拟品牌 Monthly 覆盖缺失：新增 6240 行合成月度场景数据，原始数据未覆盖，日快照与月表分别取数。
- iframe 追问被原生表单限制拦截：点击和回车均经受控消息桥发送，保留 iframe 沙箱约束。
- 追问刷新数据丢失报告身份或筛选字段：根据实际点击的报告 ID/版本恢复配置，刷新数据仍递增同一报告版本；新查询必须保留原筛选维度与比较指标。
- 报告未成功保存却被回答为完成：修改操作要求真实报告产物，允许有限修复，失败时保留原版本并明确提示。
- 多维补查超过旧响应/行数上限：实验室默认响应上限 4MB（本地项目设 8MB），查询与导出统一最多 5000 行；完整报告不接受用 TopN 替代。
- 首页历史问题点击返回原对话与回答，保留追问上下文。
- 报告完成后定位看板标题与核心指标；窄屏卡片避免数值挤压，内嵌报告通过尺寸观察与防抖计时同步高度，避免离屏 iframe 的动画帧节流影响布局。
