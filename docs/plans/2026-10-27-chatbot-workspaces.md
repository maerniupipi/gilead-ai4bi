# Chatbot 工作台 Implementation Plan

**Goal:** 在现有业务对话外增加 Chatbot 选择、切换与管理员配置，保留 DDI 的现有真实查询流程。

**Architecture:** 先采用单机配置存储的工作台版本。Chatbot 目录、开放对象和已解析的 XLSX 存入独立 SQLite 配置库；登录、模型和业务会话继续使用现有服务。会话所属 Chatbot 记录在已有 Run.insight_meta 中，无需修改业务库表结构；旧会话归入 DDI。XLSX 只读取数值，不运行公式或宏，查询限定在当前 Chatbot 的工作簿内。

**Tech Stack:** Vue 3、Vue Router、现有 Gilead 设计变量、FastAPI、SQLite、openpyxl、现有 Agent 问数/洞察循环。

## 交互设计

入口先选择业务助手，再打开现有登录框。未登录只展示内置入口，登录后按开放对象确认访问权；以后每次重新登录仍需选择。已登录刷新保留所选助手。左下角账号菜单提供切换 Chatbot、管理 Chatbot 和退出登录。切换开启新对话，各助手历史分别展示。

管理页面展示助手卡片与状态。新建/编辑包含名称、简介、业务类型、开放范围（所有人、角色、指定账号）、实验室多选与 XLSX 上传。文件上传后显示工作表、字段、行数与前几行预览；可以移除绑定。内置行为分析使用明确标记的样例数据，保留清晰的数据来源。

视觉采用吉利德红、暖白背景、细边框、圆角和克制动效。入口使用两张具有各自数据图形的业务卡片，管理页沿用现有工作台，移动端纵向排列。

## 实施步骤

1. 新增 `infrastructure/chatbots.py`、`api/routers/chatbots.py`：目录持久化、权限判断、工作簿解析与预览、创建和更新接口。使用现有账号/实验室目录；管理员始终可管理，禁用助手不可进入。
2. 修改 `api/routers/chat.py` 和 `repositories/chat.py`：请求携带 chatbot_id，校验访问和会话归属；历史问题与会话按助手筛选。旧接口缺省仍指向 DDI。
3. 新增工作簿 Lab 适配器：通过现有模型生成 SQLite SELECT，在当前助手的上传数据内只读执行；复用现有 render_report、追问和技能流程。实验室绑定限制当前助手可用实验室，未配置来源时给出明确错误。
4. 新增前端 Chatbot 状态、选择页面、卡片图形与管理页面；接入 App、登录框、左下角菜单及管理路由。用户可搜索、创建、编辑、上传、预览并保存。
5. 更新首页按助手显示名称、来源和推荐问题；请求及历史均携带当前助手 ID，切换时清理旧对话与技能选择。
6. 验证目录权限、上传边界、数据查询隔离、会话归属与分页；运行前后端相关测试及构建；用真实 admin 浏览器完成选择→登录→切换→创建→上传→保存→重新进入，检查桌面和手机布局。

## 验收边界

本次是允许样例的单机工作台版本；目录和文件配置可持久保存。绑定实验室沿用现有实验室连接，上传数据不会被静默发送给 DDI 数仓。开放范围控制助手可见性与使用权，数据源自身的行级权限继续由原有数据源控制。保留现有验收会话。
