## 第二轮 技术与数据口径

对照强生代码只读检查原生接口：既有服务提供 SSE 的 gateway v2 lab 和 trace 查询，不能使用不存在的内部 evidence 接口。吉利德副本增加原生协议分支，验证同次请求的 trace、问题、结束事件及步骤16执行证据。summary 不作为数值证据，改 SQL 后不能复用原结果。

核对独立业务库与控制库、专用读写及只读账号、新知识目录、端口和默认数据库地址；取消副本旧 .env 与旧密钥文件的 Git 跟踪，来源历史不重写。协调模型复制原 ReAct 当前启用配置，仅写入吉利德副本，真实连通测试通过。

核对 133 列、Daily Monthly 分离、按产品桥关联品牌、月份 HCO TA BU 的层级粒度、非唯一 sales_id、零目标、零基期、退货、覆盖率缺失和大于一、未来层级快照。MySQL year_month 标识符正确引用。模拟数据跨年范围与源字典样例范围分别说明。

已修正：启动缺少 python-multipart、原生 Bearer 头兼容、SQL 标识符、错误数据库假设、未经验证的主模型默认配置和单表长事务装载。装载改为小批次进度事务，压缩编码先对六表全部133列类型做只读探测，转换警告拒绝提交，保留普通 values 方式。

结论：代码和数据设计可支撑管理员模拟联调。固定共享读账号与原生用户头尚不构成吉利德区域权限；授权必须在 SQL 执行前实现，所有输出共用授权结果。
